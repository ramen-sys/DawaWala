# Dawawala front end (React + Tailwind)

Six screens from SRS 3.1.1: Registration/Login, Medication Entry, OCR Results
and Confirmation, Patient Factors, Analysis Results, History.
It runs today against a **mock backend** in the browser, so nobody is blocked.

## Run it

Needs Node 20.19 or newer.

    npm install
    npm run dev          # opens http://localhost:5173
    npm test             # logic tests (Node's built-in runner)
    node scripts/check-contrast.mjs   # WCAG AA colour check

Create any account on the login screen. Try this path: type
`Warfarin, Disprin, Metform, Amlodipine, Lasix, Brufen`, press **Choose a photo**
and pick any JPEG/PNG of at least 640x480 (the mock returns a sample label),
resolve the highlighted items, set patient factors, and run the check.

## Where things are

    src/screens/      one file per screen
    src/components/   ScoreLedger (the itemised score), SeverityBadge, WarningItem, Layout
    src/api/index.js  the ONLY place screens get data from
    src/api/mockApi.js  stand-in server (accounts, lists, OCR, analysis)
    src/mock/         demo knowledge base, name matching, JS port of the scoring engine
    src/lib/          limits (SRS Appendix A.1), image checks, formatting

## Connecting the real backend

1. Create `src/api/httpApi.js` exporting an object with the same methods as
   `mockApi.js` (`register`, `login`, `logout`, `currentUser`, `createList`,
   `getList`, `listLists`, `addNames`, `uploadImage`, `editItem`, `decideItem`,
   `removeItem`, `confirmList`, `saveFactors`, `runAnalysis`, `getAnalysis`).
2. In `src/api/index.js`, export that instead of the mock. No screen changes.
3. Send the JWT in the `Authorization: Bearer` header. Errors should come back
   as `{ code, message, fields? }` (SRS 3.1.4) and be thrown as `ApiError`.

The SRS does not define URLs. A suggested set to agree with Members 1 to 3:

    POST /api/auth/register, /api/auth/login
    POST /api/lists            GET /api/lists            GET /api/lists/{id}
    POST /api/lists/{id}/items (names)    PATCH|DELETE /api/lists/{id}/items/{itemId}
    POST /api/lists/{id}/images (multipart)
    POST /api/lists/{id}/confirm          PUT /api/lists/{id}/factors
    POST /api/lists/{id}/analyses         GET /api/analyses/{id}

An analysis must return what `analyse_payload` returns (`warnings[]`,
`band_counts`) plus `id, listId, createdAt, freshness, kb_version, kb_updated,
kb_notice, medicines, not_analysed, not_assessed, factors`. See
`src/mock/analyse.js` for the exact shape.

## How the mock stays honest

`src/mock/engine.js` is a JavaScript copy of the Python scoring module. The
test `src/mock/engine.test.js` compares it with `golden.json`, which is
generated by the real Python code:

    python scripts/make_golden.py ../dawawala-risk

If the weights or wording in Python change, regenerate the file; the test then
shows exactly what drifted. The mock knowledge base (`src/mock/kb.js`) is demo
data only and has not been clinically reviewed (SAF-09).

## Known limits

* The font (Atkinson Hyperlegible) loads from Google Fonts; offline it falls
  back to the system font.
* Photo reading is simulated. Real OCR is Member 2's service.
* Admin knowledge-base import (UC-07) is outside the UI, as the SRS says.
* Not built: dark mode, translations (English only in v1.0, SRS 5.4).
